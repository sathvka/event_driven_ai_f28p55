# Phase 2: Event Encoding

## 1. Purpose

Phase 2 converts a continuous sensor signal into a sequence of events.

Instead of treating every sensor sample as equally important, event encoding identifies significant changes in the signal. This is an initial step toward an event-driven AI pipeline.

## 2. Code File

`phase2_encoding.py`

## 3. Input Data

The script reads `phase1_dataset.csv`, which is generated by Phase 1.

For the initial experiment, the encoder uses the vibration signal and its timestamps.

## 4. How Event Encoding Works

The encoder calculates the absolute difference between consecutive vibration samples:

```python
change = np.abs(np.diff(signal))
```

It then compares each difference against a threshold:

```python
events = change > threshold
```

If the change exceeds the threshold, an event is recorded. Otherwise, no event is recorded.

The initial threshold is `0.05`.



## 5. Threshold Experiment

The script tests several thresholds:

`0.01, 0.02, 0.05, 0.10, 0.20`

For each threshold, it measures the number of events, event rate, and percentage of sample-to-sample changes that produce events.

A lower threshold generally detects more changes, while a higher threshold generally detects fewer.

The experiment also compares the normal interval (0–1 second) with the simulated bearing-degradation interval (1–2 seconds).

## 6. Output

The script:

- Plots the vibration signal.
- Displays the generated event stream.
- Compares event counts across thresholds.
- Compares event rates in the normal and bearing-degradation intervals.
- Saves threshold comparison results to `phase2_threshold_results.csv`.

## 7. Why This Matters

Event encoding may reduce how much data a later processing stage needs to examine. The threshold experiment helps us understand how the threshold affects event generation.

However, detecting an event does not itself mean that a fault has been identified. A trained AI model and further validation will be needed for fault classification.

## 8. Current Limitations

- The input data are synthetic.
- A fixed threshold may not work equally well for every operating condition.
- Noise can produce events even when the system is operating normally.
- Event generation alone does not perform AI inference.
- The laptop experiment does not demonstrate execution on the TI F28P55x NPU.

## 9. Next Step

Evaluate the event statistics, choose a suitable encoding approach, and investigate how the encoded events could be used by a future AI model.
